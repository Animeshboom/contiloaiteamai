# StudioTrack AI — Production Deployment Guide

Cloudflare Pages (web) · Render (API) · Neon (Postgres) · GitHub (source and CI). Every service runs on its free plan, and no card is required.

> **Never paste passwords, connection strings or tokens into chat, issues or commits.** Type them only into the provider dashboards, or into the git-ignored `.e2e.env` file on your machine.

Placeholders used below:
- `<API_URL>`: your Render URL, e.g. `https://studiotrack-api.onrender.com`
- `<WEB_URL>`: your Pages URL, e.g. `https://studiotrack-ai.pages.dev`

---

## 1. GitHub: branch and CI

```bash
git fetch origin
git switch deploy/cloudflare-render-neon
git push -u origin deploy/cloudflare-render-neon          # CI runs on the branch
```
GitHub → repo → **Actions**: wait for **CI** to be green (all 3 jobs). Then merge:

- GitHub → **Pull requests → New pull request** → base `main` ← compare `deploy/cloudflare-render-neon` → **Create** → **Merge** (no force-push needed),
  or locally: `git switch main && git merge --ff-only deploy/cloudflare-render-neon && git push origin main`

> Pushing to `main` also triggers the **old** Vercel project, if it is still connected. That's harmless: it was already broken and isn't used by the new deployment.

## 2. Neon: database

1. https://console.neon.tech → sign in (GitHub login is fine) → **New Project**
   - Name `studiotrack` · Postgres **16** · Region **AWS Asia Pacific (Singapore)** → **Create**
2. Project dashboard → **Connect** → keep the default branch (`main`), database `neondb`, role `neondb_owner`
   - Turn **Connection pooling OFF**: the host must *not* contain `-pooler`
   - Copy the connection string. It looks like `postgresql://neondb_owner:****@ep-xxxx.ap-southeast-1.aws.neon.tech/neondb?sslmode=require&channel_binding=require`
3. Keep it in your password manager. You paste it only into Render (step 3).

Tables are created automatically by the API on first start (`alembic upgrade head`).

*Optional, to check migrations from your PC before Render (PowerShell, from `backend/`):*
```powershell
$env:DATABASE_URL = Read-Host "Neon URL"      # pasted locally, never shown in chat
.venv\Scripts\python -m alembic upgrade head
.venv\Scripts\python -m alembic current       # should print 07a8f7ba0f96 (head)
Remove-Item Env:DATABASE_URL
```

## 3. Render: API

1. https://dashboard.render.com → sign in with GitHub → **New → Blueprint**
2. Connect the repo **StudioTrack-AI**, branch `main` → Render reads `render.yaml` and shows service **studiotrack-api** (free)
3. Fill in the prompted values:

| Key | Value |
|---|---|
| `DATABASE_URL` | the Neon connection string from step 2 |
| `APP_BASE_URL` | `https://studiotrack-ai.pages.dev` (adjust in step 5 if Pages gives a different name) |
| `CORS_ORIGINS` | `["https://studiotrack-ai.pages.dev"]` (JSON array, double quotes) |
| `CORS_ORIGIN_REGEX` | leave empty |
| `ADMIN_EMAIL` | your admin login email |
| `ADMIN_PASSWORD` | 12+ characters, from your password manager |
| `LEAD_EMAIL` / `LEAD_PASSWORD`, `ARTIST_EMAIL` / `ARTIST_PASSWORD` | optional dummy starter accounts for testing (12+ chars), e.g. `lead.test@example.com` |
| `EMAIL_SENDER`, `ANTHROPIC_API_KEY`, `GMAIL_*_JSON` | leave empty for now |

`JWT_SECRET_KEY` and `EMAIL_APPROVAL_SECRET` are generated by Render.

4. **Apply**. The first build takes ~5 minutes. In **Logs** you should see:
   ```
   Running upgrade  -> 3e6f6404fdc8, initial schema   ... -> 07a8f7ba0f96
   Bootstrap: admin <your email> created.
   Uvicorn running on http://0.0.0.0:10000
   ```
5. Copy the URL at the top of the service page: that's `<API_URL>`. Then check:
   ```bash
   curl <API_URL>/api/health
   # {"status":"ok","environment":"production","email_provider":"mcp"}
   ```
6. Service → **Settings → Build & Deploy → Auto-Deploy** should read **"After CI checks pass"**. If the Blueprint didn't apply it, set it there.

If the deploy fails with `Refusing to start in production: ...`, the message names the variable to fix. See `TROUBLESHOOTING.md`.

## 4. Cloudflare Pages: frontend

1. https://dash.cloudflare.com → **Workers & Pages → Create → Pages → Connect to Git**
2. Authorize GitHub → select **StudioTrack-AI** → **Begin setup**
3. Build settings:

| Field | Value |
|---|---|
| Project name | `studiotrack-ai` |
| Production branch | `main` |
| Framework preset | `None` |
| Build command | `npm test && npm run build` |
| Build output directory | `dist` |
| Root directory (Advanced) | `frontend` |
| Environment variables | `VITE_API_BASE_URL` = `<API_URL>` (no trailing slash) · `NODE_VERSION` = `22` |

4. **Save and Deploy**. When it finishes, your URL `https://studiotrack-ai.pages.dev` (or the name shown) is `<WEB_URL>`.
5. Project → **Settings → Environment variables**: make sure `VITE_API_BASE_URL` and `NODE_VERSION` exist for **Production** *and* **Preview**.

`VITE_API_BASE_URL` is compiled into the public JavaScript. That's expected: it's a URL, not a secret.

## 5. Connect the two

If `<WEB_URL>` differs from what you entered in step 3, go to Render → service → **Environment** and set:
- `APP_BASE_URL` = `<WEB_URL>`
- `CORS_ORIGINS` = `["<WEB_URL>"]`

Then **Save, rebuild and deploy**. (A custom domain later = add it to `CORS_ORIGINS` as a second entry.)

## 6. Verify

**a) Automated, read-only.** GitHub → **Settings → Secrets and variables → Actions → Variables**: add `API_URL` = `<API_URL>` and `WEB_URL` = `<WEB_URL>`. Then **Actions → Production smoke test → Run workflow**.

**b) Full role workflow with dummy data.** On your PC, create `.e2e.env` in the repo root (git-ignored) in an editor:
```
E2E_API_URL=<API_URL>
E2E_WEB_ORIGIN=<WEB_URL>
E2E_ADMIN_EMAIL=<admin email>
E2E_ADMIN_PASSWORD=<admin password>
```
Then run `py -3.11 scripts/e2e_workflow.py`. It creates a dummy team, lead, artist and project (`E2E …`), then runs check-in → assign → submit → partial approval with revision feedback → resubmit → approve → complete. It checks permissions and revocation, then deactivates the dummy accounts. Delete `.e2e.env` afterwards.

**c) Browser.** Open `<WEB_URL>`, sign in as the admin, press F5 on a nested page (e.g. `/admin/projects`), and check DevTools → Console/Network for no CORS or 404 errors.

**d) Secure the bootstrap.** Under **Settings**, change the admin password, then delete `ADMIN_PASSWORD` (and any `LEAD_`/`ARTIST_PASSWORD`) from Render → Environment.

## Everyday updates (the pipeline)

```
edit with Claude Code → git commit → git push origin main
   ├─ GitHub Actions CI (≈4–6 min) ── fails? → nothing deploys to Render; fix and push again
   ├─ Render: waits for CI ✔ → builds image → migrates → health check → switches traffic (zero-downtime)
   └─ Cloudflare Pages: npm test && build → publishes (a failed build keeps the previous version live)
```
- Work on a branch and open a PR to get CI plus a Cloudflare **preview URL** before merging.
- Frontend- or docs-only commits don't redeploy the API (Render build filter).
- After a deploy: run **Production smoke test** from the Actions tab.

## Database migrations

1. Change models in `backend/app/models/`, then generate a migration locally against your Docker DB:
   ```bash
   docker compose up -d db
   cd backend && .venv/Scripts/alembic revision --autogenerate -m "describe change"
   ```
2. Review the generated file. It must be **additive** (no drops or renames of live columns, and new columns nullable or with a server default).
3. Push. CI applies it to an empty Postgres and runs `alembic check`. Render applies it at start.
4. Risky change? First, Neon console → **Branches → Create branch** from `main` (an instant copy, which works as a restore point).

## Rollback

| What | How |
|---|---|
| API code | Render → service → **Events** → pick the last good deploy → **Rollback**. Or `git revert <sha> && git push` (never force-push). |
| Frontend | Cloudflare → Pages project → **Deployments** → previous deployment → **⋯ → Rollback to this deployment** |
| Database | Neon → **Restore** (point-in-time within the free plan's history window) or switch to the branch created before the migration. Restores replace data, so do this **only deliberately**. |
| Config | Render → Environment: revert the variable → Save, rebuild and deploy |

Migrations are forward-only. If a deploy with a new migration must be rolled back, the old code still works because migrations are additive.

## Free-tier limits

| Provider | Limit | Impact |
|---|---|---|
| Render free | Sleeps after ~15 min idle. Cold start ~30–60 s. 750 instance-hours/month. Ephemeral disk. | First login after idle is slow. **Uploaded attachments are lost on every deploy/restart.** Reminders and email dispatch pause while asleep. |
| Neon free | 0.5 GB storage, monthly compute-hour allowance, scales to zero after 5 min idle | Sub-second wake on first query. Fine for a prototype. |
| Cloudflare Pages free | 500 builds/month, 1 concurrent build | Plenty |
| GitHub Actions | Free minutes for your account type (unlimited for public repos) | CI is ~5 min per push |

Upgrade path, when needed: Render Starter plus a persistent disk (`/app/data`), or object storage for uploads.
